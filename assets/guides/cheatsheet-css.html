Anatomy of a CSS rule

    
Every CSS rule, no matter how complicated the project gets, is built from the same three parts.


    


      

        

          
          
          
        

        


p {
  color: white;
  font-size: 16px;
}

        

      


      


        

          SELECTOR
          
p is a selector: it says which elements in your HTML code this rule applies to. Just a tag name like this is an element selector: it matches every <p> on the page, like the ones in the HTML guide's structure example. The { opens the declaration block; everything up to the matching } belongs to this rule.

        


        

          DECLARATIONS
          
Each line inside the braces is a declaration: a property (color, font-size) and a value (white, 16px), separated by a colon, ending in a semicolon: property: value;, the same pattern every time.

        


        

          CLOSING BRACE
          
} closes the declaration block, matching the { from the selector line. Miss it and every rule written after gets swallowed into this one.

        


      


      

        

        

        

        


        

        

        

        


        

        

        

        

      


    

  


  

  

    
Selectors

    
Every kind of selector CSS gives you for targeting elements, each shown as a complete rule you could actually write.


    

      

        
By tag, class, or id

        

          
p { }:
element selector: targets every <p> in your HTML, matched by tag name alone. Works the same for every tag from the HTML guide's tag reference: div { }, span { }, header { }, nav { }, main { }, section { }, footer { }, h1 { }, a { }, strong { }, em { }, ul { }, ol { }, li { }, img { }, video { }, audio { }, iframe { }, form { }, input { }, button { }, label { }, textarea { }, select { }. Any tag name becomes a selector just by dropping the angle brackets.

          
.card { }:
class selector: targets every element with card among its classes, e.g. <div class="card">. An element can carry more than one class at once, separated by spaces: class="card featured" gives one element both a card class and a featured class, so it would be matched by either .card or .featured.

          
#header { }:
id selector: targets the one element with id="header" in its HTML tag. Unlike a class, an id should only appear once per page.

          
[type="text"] { }:
attribute selector: targets only elements carrying this exact attribute set to this exact value. <input type="text"> matches; <input type="checkbox"> or a plain <div> does not. The brackets pair an attribute name (type) with the value it must equal ("text").

          
* { }:
universal selector: targets every single element on the page.

        

      


      

        
By relationship

        

          
div p { }:
descendant: a <p> anywhere inside a <div>, no matter how deeply nested. Two selectors separated by a space.

          
div > p { }:
child: a <p> that is a direct child of a <div> only, not nested any deeper. A "child" here means a nested HTML element, one level in, not plain text typed directly into the div.

          
h1 + p { }:
adjacent sibling: a <p> that comes immediately after an <h1>, sharing the same parent.

          
h1, h2, h3 { }:
group: applies the same declarations to all three, separated by commas, instead of writing the same rule three times.

        

      


      

        
By state or position (pseudo-classes)

        

          
a:hover { }:
a is just the tag selector; :hover isn't link-specific, it fires while the mouse is over any element. Swap in another selector, e.g. button:hover { } or .card:hover { }, to use it elsewhere.

          
input:focus { }:
applies while the element is focused, e.g. a text field the user has clicked into.

          
li:first-child { }:
li is just the tag selector; :first-child isn't list-specific, it matches whichever element is first inside its parent, of any tag. Swap in another tag, e.g. p:first-child { }, to use it elsewhere.

          
li:last-child { }:
same idea, but for whichever element is last inside its parent.

        

      


      

        
By part of an element (pseudo-elements)

        

          
p::first-line { }:
targets just the first line of the element's text, not the whole thing.

          
.quote::before { }:
a spot right before the element's content, invented by CSS: no matching tag exists in your HTML. Needs a content declaration to show anything, e.g. content: "“"; inserts an opening curly quote.

        


        
Renders as

        
this is a quote

      

    

  


  

  

    
The box model

    
Every element on a page is a box made of four layered parts, from the inside out. Each line below sets one layer.


    


      

        

          
          
          
          
        

        


.box {
  width: 200px;
  padding: 20px;
  border: 1px solid black;
  margin: 10px;
}

        

      


      


        

          CONTENT
          
Sets the size of the content box itself: the innermost layer. This is the number width / height directly controls.

        


        

          PADDING
          
By default, padding is added on top of width, not carved out of it. It doesn't shrink the content box, it makes the whole element bigger. It's the space inside the border, between it and the content, and takes on the element's own background, so visually it reads as part of the box.

        


        

          BORDER
          
The edge itself: the visible line separating padding from margin.

        


        

          MARGIN
          
Space outside the border, pushing this box away from its neighbors. Always transparent: margin never shows the box's background.

        


      


      

        

        

        

        


        

        

        

        


        

        

        

        


        

        

        

        

      


    


    
By default, width only sizes the content box. Padding and border stack on top, making the element wider than the number you typed. Add box-sizing: border-box; to include them in that width instead. Most sites (including this one) set it once for every element with the universal selector: * { box-sizing: border-box; }.

  


  

  

    
Layout: flexbox & grid

    
Two different tools for arranging a group of elements. Add these as declarations inside a rule's { }, the same shape as the anatomy example near the top of this page. Flexbox for a single row or column, grid for a true two-dimensional layout.


    

      

        
Flexbox

        

          
display: flex:
turns a container into a flex row; its children line up side by side by default, staying on one line and shrinking to fit.

          
flex-wrap: wrap:
lets items flow into additional rows once they run out of space, instead of shrinking to fit on one line.

          
flex-direction: column:
switches the row to a column instead.

          
justify-content: center:
spacing along the main axis. center, space-between, and flex-start are common values.

          
align-items: center:
alignment across the cross axis, the direction perpendicular to flex-direction.

          
gap: 16px:
space between children, no margin hacks needed.

        

      


      

        
Grid

        

          
display: grid:
turns a container into a grid.

          
grid-template-columns: repeat(3, 1fr):
defines the columns. This creates three equal columns: fr means “fraction”, one shared portion of the available space, so 1fr 1fr 1fr splits it three ways evenly. repeat(3, 1fr) is just a shortcut for writing that out.

          
gap: 16px:
space between rows and columns alike.

        

      

    

  


  

  

    
Typography & color

    
Properties for styling text and color. Add these as declarations inside a rule's { }, the same shape as the anatomy example near the top of this page.


    

      

        
Typography

        

          
font-family: "Helvetica Neue", Arial, sans-serif:
the browser tries each one left to right, using the first it has installed: Helvetica Neue, then Arial if that's missing, then sans-serif, a generic fallback (not a real font name) meaning "whatever sans-serif font this system has." Quotes are only needed around a name containing a space, like "Helvetica Neue". Single-word names like Arial don't need them.

          
font-size: 16px:
text size.

          
font-weight: bold:
boldness, e.g. normal or bold.

          
line-height: 1.5:
vertical spacing between lines of text.

          
text-align: center:
left, center, right, or justify.

        

      


      

        
Color

        

          
color: red:
text color.

          
background: black:
an element's background.

          
color: #ff0000:
a hex color value; also fine as a named color like red.

          
color: rgba(255, 0, 0, 0.5):
red, green, blue, and an opacity from 0 (invisible) to 1 (solid). Works anywhere a color is expected, e.g. also in background.

          
background: transparent:
the keyword for fully invisible, equivalent to an alpha of 0, e.g. rgba(0, 0, 0, 0). Handy for removing a background without knowing what color it currently is. For partial transparency, like 50%, there's no keyword: set that same alpha number to 0.5 instead, e.g. rgba(0, 0, 0, 0.5).

        

      

    


    
Every font listed above has to already be installed on the visitor's device. To use a specific font that might not be, load it yourself with @font-face, then reference the name you gave it like any other font:


    

      

        


@font-face {
  font-family: "My Font";
  src: url("fonts/my-font.woff2");
}

body {
  font-family: "My Font", sans-serif;
}

        

      

    


    
The font-family inside @font-face is a name you invent. It doesn't have to match the file name. src points to the actual font file, usually a .woff2 sitting somewhere in your project. Once declared, use that same name in any font-family list, always with a generic fallback in case the file fails to load.

  


  

  

    
Responsive design

    
Making a layout adapt to different screen sizes, from a phone up to a wide desktop.


    
Flexbox and grid layouts already adjust automatically as the browser window gets narrower. Items shrink or wrap on their own, without any extra code. A media query is only needed when you want something to change more deliberately, like going from three columns to one instead of just narrower columns. Try it yourself: make this browser window narrower and watch the page respond.


    


      

        

          
          
        

        


.grid {
  grid-template-columns: repeat(3, 1fr);
}

@media (max-width: 700px) {
  .grid {
    grid-template-columns: 1fr;
  }
}

        

      


      


        

          DEFAULT RULE
          
The normal rule: applies at any screen size unless something more specific overrides it. Here, three equal columns.

        


        

          MEDIA QUERY
          
@media (max-width: 700px) { … } wraps a whole set of rules that only apply once the browser window is 700px wide or narrower. Inside, the same selector gets a new value. This is how three columns become one on a phone.

        


      


      

        

        

        

        


        

        

        

        

      


    


    

      

        
Units for responsive sizing

        

          
width: 50%:
relative to the parent element's size.

          
width: 50vw:
1% of the viewport's width per unit, so 50vw is half the browser window's width. vh is the same idea for height.

          
font-size: 2rem:
relative to the root (<html>) font size. em is the same idea, but relative to the current element's own font size.

          
font-size: clamp(16px, 4vw, 24px):
a value that scales with the viewport but never goes below or above the limits you give it, here never smaller than 16px or larger than 24px.

        

      

    

  


  

  

    
The cascade

    
"Cascading" is the C in CSS: when more than one rule targets the same element, this is how the browser decides which one wins. Two forces decide it: how specific each selector is, and (only when specificity ties) the order the rules are written in.


    
Start with the simple case: when two rules use the exact same selector, the one written later in the file wins.


    

      

        


.title { color: blue; }
.title { color: red; } /* wins, written later */

        

      

    


    
But the moment one selector is inherently stronger than the other, specificity decides instead. Order stops mattering, no matter which rule comes first or last in the file:


    


      

        

          
          
          
        

        


p {
  color: black;
}

.title {
  color: blue;
}

#title {
  color: red;
}

        

      


      


        

          ELEMENT
          
The weakest selector type. Any more specific rule beats it, no matter the order it's written in.

        


        

          CLASS
          
Stronger than an element selector: wins regardless of order. Even if this rule were moved above the p rule, class still wins: specificity outranks position.

        


        

          ID
          
Strongest of the three. Wins over both rules above, every time. Move this whole block to the very top of the file and it still wins.

        


      


      

        

        


        

        

        

        


        

        

        

        

      


    


    

      

        
Two rungs above the ladder

        

          
style="…":
written directly inside an HTML tag, e.g. <p style="color: red;">. Beats every selector before or in the CSS file, regardless of specificity or order.

          
!important:
added at the end of a value inside a normal declaration, e.g. color: red !important;. Works in an external stylesheet, an internal <style> block, or even inline. Overrides the entire system: wins over everything except another !important. Generally worth avoiding, it makes the next conflict much harder to debug.
