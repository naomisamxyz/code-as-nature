Create a multiplayer p5.js sketch (no server needed)

    
Change a color together. Click the canvas to change its color for everyone watching.

    
We are making a sketch that everyone can change at the same time: when one person clicks the canvas, its color changes on every screen. Normally this would need a server of our own to pass information between computers. Instead, we use p5.party, a library that provides the shared connection for us, so we don't need to build or run a server. This example follows the p5.party shared-data approach, and its public demo server is intended for classroom experiments.

    

      

        

          
p5.party:
p5party.org

        

      

    

    


    

      
    


    

      
    


    
Open editor.p5js.org, sign in, and create a new sketch.

    
Expand the file sidebar to see index.html and sketch.js.

This guide uses p5.js 1.11.10. Its preload() function loads the shared data before the sketch starts. Copy the HTML exactly as shown.

    

    
Select index.html, delete its contents, and paste:

Replace sketch.js

    
Select sketch.js, delete its contents, and paste:

    


      

        

          
          
          
          
          
          
        

        


let shared;

function preload() {
  partyConnect(
    "wss://demoserver.p5party.org",
    "code-as-nature"
  );

  shared = partyLoadShared("background", {
    color: "white"
  });
}

function setup() {
  createCanvas(400, 400);
}

function draw() {
  background(shared.color);
}

function mousePressed() {
  if (
    mouseX < 0 || mouseX > width ||
    mouseY < 0 || mouseY > height
  ) {
    return;
  }

  if (shared.color === "white") {
    shared.color = "pink";
  } else {
    shared.color = "white";
  }
}

        

      


      


        

          SHARED VARIABLE
          
Will hold the object everyone shares.

        


        

          CONNECT
          
Connects the sketch to the group. Everyone using the same server address and project name "code-as-nature" joins together.

        


        

          LOAD SHARED DATA
          
Loads the shared object "background". The white starting value is only used when it is first created.

        


        

          DRAW
          
Paints the background with the shared color, so every screen shows the same one.

        


        

          INSIDE CANVAS ONLY
          
Ignores clicks outside the canvas.

        


        

          TOGGLE COLOR
          
Switches the shared color between white and pink. Because it is shared, it changes on everyone's screen.

        


      


      

        

        

        

        


        

        

        

        


        

        

        

        


        

        

        

        


        

        

        

        


        

        

        

        

      


    

    
The first if in mousePressed() makes the sketch only respond to clicks inside the canvas.

  


  

    
How it works

    
    
      
  • partyConnect() connects the sketch to the group.
    • 
      
  • partyLoadShared() loads a value everyone shares.
    • 
      
  • background(shared.color) displays that value.
    • 
      
  • Clicking changes shared.color, which updates everyone’s screen.
    • 
    

    
The white starting value is used when the shared object is first created. Joining an existing session loads its current color.

Multiplayer with a server

    
This example starts with a server.

    

    
  


  

    
How Collective Particles works

    
Collective Particles lets everyone visiting the website interact with the same field of particles. Each browser draws the field, while one shared server calculates what happens to it.


    
Where the files are stored

    
The GitHub repository is the online project folder. It contains both the portfolio website and the particle application:

    
Portfolio-Website-2/
│
├── week7/
│   ├── index.html
│   ├── config.js
│   ├── embed.js
│   └── particles.css
│
└── collective-particles/
    ├── server.js
    ├── shared/
    │   └── simulation.js
    └── public/
        ├── embed.html
        ├── sketch.js
        └── style.css

    
Two services make the project work online:

    
    
      
  • GitHub Pages displays the portfolio.
    • 
      
  • Render runs the particle application’s server.
    • 
    


    
Why the code is on GitHub and Render

    
GitHub holds the source code and its change history. Render uses that repository to obtain the code it needs to run.

    
When the application is deployed, Render downloads the selected version from GitHub, installs its libraries, and builds a runnable copy.

    
The update process is:

    
Edit on the computer → push to GitHub → Render builds and runs the updated application

    
Render keeps that built copy. A normal restart or wake from sleep runs the existing copy; it does not need to download the code from GitHub again.

    
The simulation does not inherently require GitHub. GitHub is the delivery and version-history system chosen for this project.


    
How Week 7 displays the sketch

    
Inside week7/, index.html contains the portfolio page’s heading, text, and navigation.

    
config.js stores the particle application’s address:

    

      

        


https://collective-particles.onrender.com

        

      

    

    
embed.js uses that address to create an iframe: a window displaying another webpage inside the portfolio page. It opens the application’s embed.html page from Render.

    
particles.css controls the size and appearance of that window.

    
The result looks like one website, although the surrounding portfolio comes from GitHub Pages and the interactive sketch comes from Render.


    
What runs on Render

    
Render starts server.js.

    
A server is a running program that receives connections and responds to them. Here, it keeps one shared particle field for all visitors.

    
server.js uses shared/simulation.js to calculate particle positions, attraction, repulsion, vortex movement, and color absorption. It updates the field 30 times per second.

    
These calculations happen on Render rather than separately on each visitor’s computer.


    
What runs in the browser

    
Render also delivers webpage files to each visitor:

    
    
      
  • public/embed.html loads the interactive page and its libraries.
    • 
      
  • public/sketch.js draws the particles using p5.js and detects mouse or touch actions.
    • 
      
  • public/style.css styles the interface.
    • 
    

    
Although these files are stored on Render, their drawing and interaction code runs in the visitor’s browser.

    
The browser displays the particle positions it receives from the server.


    
What Socket.IO does

    
Socket.IO is a JavaScript library that carries messages between browsers and the server.

    
In sketch.js, this line opens the connection:

    

      

        


const socket = io();

        

      

    

    
socket is simply the name given to that connection. It is not another website or hosting service.

    
Because the sketch loaded from Render, it connects back to that Render server.

    
When someone presses the canvas, the browser sends their pointer position, selected force, and whether they are pressing.

    
The server receives that message, updates the shared particles, and sends their new positions and colors to everyone. Each browser then redraws the field.

    
The exchange works like this:

    

      

        

          
Your browser:
“Someone is pressing here with the vortex tool.”

          
The server:
“Here is how that changes the particles.”

          
Everyone’s browser:
Draws the updated particles.

        

      

    


    
What is saved—and what resets

    
Render keeps the application code in its deployed build. However, the current particle positions, colors, and movements exist only in the running server’s memory.

    
This project has no database or permanent save system. Restarting the server resets the particle field, while the application code remains available to run again.

    
Every visitor connects to the same server, so their actions affect the same particles. The computer used to build the project can be turned off because Render runs the application online. The free hosting service can sleep when unused.

  


  

    
Self-hosting

    
Self-hosting means your own computer acts as the server, instead of a hosting service like Render.


    
What a local server does

    
A server is a program that runs continuously and waits for connections. It listens on a port, a numbered door on your computer, and when a browser connects to that port, the server answers it by sending back webpage files or by exchanging messages, as Socket.IO does in this project.

    
A local server is the same program running on your own computer, so the computer you are working on is also the one every visitor connects to.


    
Start the server

    
    
      
  1. Install Node.js, which runs JavaScript programs outside the browser.
    2. 
      
  2. Open a terminal in the folder that contains server.js, in this project the collective-particles folder.
    3. 
      
  3. The first time only, install the libraries the project needs, such as Socket.IO:
    4. 
    

    

      

        


npm install

        

      

    

    
    
      
  1. Start the server:
    2. 
    

    

      

        


node server.js

        

      

    

    
The terminal stays busy while the server is running, and it may print a message saying which port it is listening on. Check server.js for the port number it uses.

    
Open that address on your own computer to test it, for example:

    
http://localhost:3000

    
To stop the server, click the terminal and press Ctrl + C.


    
Connect from another device

    
localhost only works on your own computer. Other devices on the same Wi-Fi or network need your computer’s local network address instead. On a Mac, you can find it in System Settings → Wi-Fi → Details, or by running ipconfig getifaddr en0 in the terminal. On Windows, run ipconfig and look for the IPv4 address.

    
Then use that address with the same port:

    
http://192.168.1.20:3000

    
This only works while your computer is on, the server is running, and the other devices are on the same network.


    
Over the internet

    
To let people connect from outside your network, your computer has to be reachable from the internet. There are two common ways to do this:

    
    
      
  • Set up port forwarding on your router, so connections arriving at a chosen port are passed on to your computer.
    • 
      
  • Use a tunneling tool such as ngrok or Cloudflare Tunnel, which gives your locally running server a public web address without changing your router.
    • 
    

    
Opening your computer to the internet has security risks, so only expose a server you understand and are comfortable sharing.


    
Compared with a hosting service

    
A hosting service such as Render keeps the server running on its own computers, so your computer can be turned off. When you self-host, the server runs only while your computer is on and connected, and you are responsible for keeping it running.
