Project outcome and tools

    
Create an animated AR character website with Mixamo, <model-viewer>, and GitHub Pages.

    
You will

    
    
      
  1. Generate a 3D humanoid character.
    2. 
      
  2. Rig and animate it with Adobe Mixamo.
    3. 
      
  3. Create character.glb for the webpage and Android AR.
    4. 
      
  4. Create character.usdz for iPhone and iPad AR.
    5. 
      
  5. Build and publish a small website, then share it through a URL or QR code.
    6. 
    

    
No Unity project, app-store submission, or web-server programming is required.

    
Tools

    
    
      
  • An AI 3D character-generation service
    • 
      
  • Adobe Mixamo
    • 
      
  • Blender
    • 
      
  • Apple Reality Converter on a Mac
    • 
      
  • GitHub
    • 
      
  • Google's <model-viewer>

Prepare the character

    
Generate or choose a humanoid character. For the easiest Mixamo workflow, it should:

    
    
      
  • Have one head, two arms, and two legs.
    • 
      
  • Stand upright, face forward, and use a neutral T-pose or A-pose.
    • 
      
  • Have its arms separated from its body and its legs separated from one another.
    • 
      
  • Avoid large wings, tails, props, or disconnected body parts.
    • 
      
  • Use a relatively low polygon count and include textures.
    • 
    

    
Download it as FBX, OBJ, ZIP, or another format Mixamo accepts.

  


  

    
Rig the character in Mixamo

    
    
      
  1. Open Mixamo, sign in with a personal Adobe ID, and select Upload Character.
    2. 
      
  2. Place the chin, wrist, elbow, knee, and groin markers according to Mixamo's guide.
    3. 
      
  3. Select the appropriate finger setting and start automatic rigging.
    4. 
      
  4. Preview the rigged character.
    5. 
    

    

      

        

          
If the rig fails:
check that the body parts are visually distinct and that the original model is in a neutral pose.

        

      

    

  


  

    
Add an animation

    
    
      
  1. Choose an animation that loops clearly: dancing, waving, idle movement, walking in place, stretching, or looking around.
    2. 
      
  2. Adjust speed, arm spacing, or animation length, then select Download.
    3. 
    

    

      

        
Download settings

        

          
Format:
FBX Binary

          
Skin:
With Skin

          
Frames per second:
30

          
Keyframe reduction:
None

        

      

    

    
The resulting FBX should contain the character, skeleton, textures, and animation.

  


  

    
Create the GLB file

    
GLB packages the model, skeleton, animation, materials, and textures into one web-friendly file.

    
    
      
  1. Open Blender and import the animated Mixamo FBX through File → Import → FBX.
    2. 
      
  2. Play the timeline. Confirm that the character and textures are visible and the skeleton and animation move correctly.
    3. 
      
  3. Select the character and armature, then choose File → Export → glTF 2.0.
    4. 
      
  4. Choose GLB and include materials, skinning, animations, selected objects when applicable, and any shape keys.
    5. 
      
  5. Export as character.glb.
    6. 
    

    
Test the GLB in the <model-viewer> editor before continuing.

  


  

    
Create and test the USDZ file

    
Apple devices use USDZ for AR Quick Look. Supply a dedicated ios-src; automatic conversion does not reliably preserve skeletal animation.

    
    
      
  1. Open Apple's Reality Converter on a Mac and drag in character.glb.
    2. 
      
  2. Check the character, textures, scale, orientation, and animation.
    3. 
      
  3. Export as character.usdz.
    4. 
      
  4. Transfer it to an iPhone or iPad and open it in Apple Quick Look.
    5. 
      
  5. Enter AR mode and confirm its scale, textures, and animation.
    6. 
    

    

      

        

          
If animation is missing:
confirm in Blender that the character uses one skeleton and that the animation is baked. Export again, reopen it in Reality Converter, and test the new USDZ. Simple characters with baked animation are more reliable than multiple skeletons, constraints, modifiers, procedural effects, or complex materials.

        

      

    

  


  

    
Create the website

    
Create a project folder containing three files:

    
my-ar-character/
├── index.html
├── character.glb
└── character.usdz

    
Add this to index.html:

    


      

        

          
          
          
          
          
          
          
        

        


<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>My AR Character</title>
    <script type="module"
      src="https://ajax.googleapis.com/ajax/libs/model-viewer/4.3.1/model-viewer.min.js">
    </script>
    <style>
      * { box-sizing: border-box; }
      body {
        margin: 0;
        min-height: 100vh;
        background: #e8ff52;
        color: #111;
        font-family: Arial, Helvetica, sans-serif;
      }
      main {
        display: grid;
        grid-template-rows: auto 1fr;
        min-height: 100vh;
      }
      header { padding: 18px 22px; }
      h1 { margin: 0; font-size: clamp(1.5rem, 5vw, 3rem); }
      p { max-width: 42rem; line-height: 1.4; }
      model-viewer {
        width: 100%;
        min-height: 70vh;
        background: transparent;
      }
      .ar-button {
        position: absolute;
        right: 20px;
        bottom: 20px;
        padding: 12px 18px;
        border: 2px solid #111;
        border-radius: 999px;
        background: #fff;
        color: #111;
        font: inherit;
        font-weight: bold;
        cursor: pointer;
      }
      .ar-button:focus {
        outline: 3px solid #725cff;
        outline-offset: 3px;
      }
    </style>
  </head>
  <body>
    <main>
      <header>
        <h1>My AR Character</h1>
        <p>Drag to rotate, scroll or pinch to zoom, or place the character in your space.</p>
      </header>
      <model-viewer
        src="character.glb"
        ios-src="character.usdz"
        alt="An animated three-dimensional character"
        camera-controls autoplay loop
        shadow-intensity="1" exposure="1"
        ar ar-placement="floor" ar-scale="auto"
        ar-modes="webxr scene-viewer quick-look">
        <button class="ar-button" slot="ar-button">
          View in your space
        </button>
      </model-viewer>
    </main>
  </body>
</html>

        

      


      


        

          HEAD
          
Everything the page needs before it can display anything: metadata, the model-viewer script, and all the CSS.

        


        

          BODY
          
What actually appears on screen — the page layout wrapping the header and the AR viewer.

        


        

          LOAD MODEL-VIEWER
          
Loads Google's <model-viewer> custom element from a CDN. Everything below depends on this one script.

        


        

          PAGE STYLES
          
Ordinary CSS: page layout, background, and the floating AR button's shape and position. None of it is AR-specific — model-viewer is just another element to style.

        


        

          HEADER
          
The title and instructions shown above the viewer.

        


        

          THE VIEWER
          
The 3D viewer itself, configured entirely through attributes. See what each one does below.

        


        

          BUTTON
          
A custom trigger dropped into model-viewer's ar-button slot, so it can be styled like the rest of the page instead of using the library's default button.

        


      


      

        

        

        

        


        

        

        

        


        

        

        

        


        

        

        

        


        

        

        

        


        

        

        

        


        

        

        

        

      


    

    

      

        
Important attributes

        

          
src:
loads the GLB used by the webpage and Android.

          
ios-src:
provides the dedicated Apple USDZ.

          
autoplay and loop:
start and repeat the animation.

          
camera-controls:
allows rotation and zoom.

          
ar:
enables the AR button.

          
ar-placement="floor":
uses a horizontal surface. Change floor to wall for a wall placement.

          
ar-scale="auto":
lets viewers resize the character.

          
ar-modes:
provides WebXR, Android Scene Viewer, and Apple Quick Look.

Opening index.html directly may cause browser restrictions. Test through a local web server or GitHub Pages.

    
    
      
  • Check that the character loads, its textures appear, and its animation plays.
    • 
      
  • Check that rotation and zoom work and the AR button appears on a supported phone.
    • 
      
  • Check that Android loads the GLB and Apple devices load the USDZ.

Publish with GitHub Pages

    
    
      
  1. Create a public GitHub repository named something like my-ar-character.
    2. 
      
  2. Upload and commit the HTML, GLB, and USDZ files.
    3. 
      
  3. Open Settings → Pages.
    4. 
      
  4. Choose Deploy from a branch, main, and /root.
    5. 
      
  5. Save and wait for the site to publish.
    6. 
    

    
https://USERNAME.github.io/REPOSITORY-NAME/

    
GitHub Pages provides the HTTPS required by browser-based WebXR.

  


  

    
Test the published project

    
Desktop

    
Check that the character appears, loops, rotates when dragged, and zooms when scrolled.

    
Android

    
Tap View in your space, allow camera access, scan a horizontal surface, and place the character. Android normally uses the GLB through WebXR or Scene Viewer.

    
iPhone and iPad

    
Open the site in Safari and tap View in your space. Quick Look should load the dedicated USDZ. Place the character and confirm its animation.

  


  

    
Create a QR code

    
Point it to the GitHub Pages URL, not directly to either model file.

    
The code can appear in a wall label, poster, publication, sculpture, sticker, exhibition map, projection, or portfolio.

  


  

    
Troubleshooting

    

      

        
Common problems

        

          
White or missing textures:
Include textures during Blender export, use GLB, and convert unsupported procedural materials to image textures.

          
No webpage animation:
Test the GLB in the <model-viewer> editor, include animation during export, and confirm autoplay. For several animations, specify animation-name="Dance".

          
No animation in iPhone AR:
Confirm ios-src, open the USDZ directly, bake the animation, and use one skeleton and one animation.

          
Wrong direction:
Correct and apply rotation in Blender, then export both formats again.

          
Wrong scale:
Adjust scale before export and test the USDZ on a device.

          
No AR button:
The browser or device may not support the requested AR modes. Interactive 3D should still work.

          
GitHub Pages 404:
Check index.html, the branch, folder, and filename capitalization, then wait several minutes.

        

      

    

  


  

    
A Character Enters the World

    
Create or generate a humanoid character, give it one movement using Mixamo, and publish it as a website that lets visitors view it in 3D and place it in a physical environment.

    
Consider

    
    
      
  • What scale should the character occupy, and where does it belong?
    • 
      
  • Does its movement change meaning in a bedroom, street, gallery, classroom, or landscape?
    • 
      
  • Is it visiting, haunting, performing for, or attempting to escape the physical world?
    • 
      
  • What relationship exists between the webpage, screen, and surrounding space?
