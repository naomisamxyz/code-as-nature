Creating a Supabase database (optional)

    
Last week, our meme generator requested random text and images from APIs. This week, we will save them to a shared Supabase database so we can retrieve them later.

    
Everyone will use the same database. You do not need to create your own Supabase account, project, or table.

    

      Skip this section for the class exercise. These instructions are for creating your own database in the future.
    
Go to Supabase, create an account, and create a new project.


    
Create a table

    
Go to Table Editor → New Table.

    

      

        

          
Name:
memes

          
Schema:
public

          
Row Level Security (RLS):
ON

          
Realtime:
OFF

        

      

    


    
Create these columns:

    

      

        

          
id:
int8, Identity / automatically generated, does not allow NULL, Primary Key.

          
image_url:
text, no default, does not allow NULL.

          
meme_text:
text, no default, allows NULL.

          
created_at:
timestamptz, default now(), does not allow NULL.

        

      

    


    
Allow public inserts

    
Go to memes → RLS / Policies → Create Policy → Create a policy from scratch.

    

      

        

          
Policy name:
Allow public meme uploads

          
Policy command:
INSERT

          
Target roles:
anon

          
WITH CHECK expression:
true

        

      

    

    
This allows visitors who are not logged in to add rows.


    
Allow public reads

    
Go to memes → RLS / Policies → Create Policy → Create a policy from scratch.

    

      

        

          
Policy name:
Allow public meme reading

          
Policy command:
SELECT

          
Target roles:
anon

          
USING expression:
true

        

      

    

    
This allows visitors who are not logged in to read rows.


    
Get your connection information

    
Go to Project Settings → API. Copy the Project URL and Publishable Key.

    
The Project URL identifies the project. The Publishable Key allows frontend JavaScript to access it according to the RLS policies.

    
Never put a secret or service-role key in a public website.

Create the save function

    
Add this underneath your existing generateMeme() function:


    


      

        

          
          
          
          
          
        

        


async function saveMeme() {

  const { error } = await supabaseClient
    .from("memes")
    .insert({
      image_url: memeImage.src,
      meme_text: memeText.textContent
    });

  if (error) {
    console.error("Could not save meme:", error);
  } else {
    console.log("Meme saved!");
  }
}

        

      


      


        

          ASYNC FUNCTION
          
async lets this function wait for an online operation to finish.

        


        

          INSERT ROW
          
Connects to the memes table and inserts a new row. await waits until Supabase responds. Supabase automatically creates the id and created_at values, so we don't need to send them.

        


        

          HANDLE RESULT
          
Prints the result in the browser console.

        


        

          IMAGE URL
          
Saves the URL currently used by our meme image.

        


        

          MEME TEXT
          
Saves the text currently displayed on the meme.

Retrieve and display the memes

    
Add this function to script.js:


    


      

        

          
          
          
          
          
          
          
        

        


async function getMemes() {

  const { data, error } = await supabaseClient
    .from("memes")
    .select("*")
    .order("id", { ascending: true });

  if (error) {
    console.error("Could not retrieve memes:", error);
    return;
  }

  data.forEach(meme => {
    const memeDiv = document.createElement("div");
    memeDiv.className = "meme";

    const image = document.createElement("img");
    image.src = meme.image_url;
    image.className = "meme-image";

    const text = document.createElement("p");
    text.textContent = meme.meme_text;
    text.className = "meme-text";

    memeDiv.appendChild(image);
    memeDiv.appendChild(text);

    memeDatabase.appendChild(memeDiv);
  });
}

        

      


      


        

          RETRIEVE ROWS
          
Retrieves every row from the memes table, selecting all columns and ordering by id so rows appear in the order they were created.

        


        

          REPEAT FOR EACH ROW
          
Repeats the code inside once for every row returned by Supabase, turning each one into a meme element on the page.

        


        

          CREATE CONTAINER
          
Creates a container <div> for one meme.

        


        

          CREATE IMAGE
          
Creates its image from image_url.

        


        

          CREATE TEXT
          
Creates its text from meme_text.

        


        

          ASSEMBLE MEME
          
Puts the image and text inside the meme container.

        


        

          ADD TO PAGE
          
Adds the finished meme to the page.

Create the database grid

    
Add to style.css:

    

      

        


#meme-database {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(300px, 1fr));
  gap: 20px;
}

#meme-database .meme {
  width: 100%;
  height: auto;
  aspect-ratio: 1 / 1;
  min-width: 0;
}

        

      

    

    
auto-fit changes the number of columns based on the available space. minmax(300px, 1fr) gives each column a minimum width of 300px while allowing it to grow.

    
We target #meme-database .meme specifically so only memes inside the database are affected — the original .meme style can stay 400px × 400px.

  


  

    
Database, APIs, and Manovich

    
A database stores and organizes data. An API lets programs retrieve, send, or modify that data.

    
Last week, we used APIs to retrieve data. Now we use Supabase's API to send data into our shared database:


    
TEXT API  ──→ text  ──┐
                       ├──→ MEME → SAVE → DATABASE
IMAGE API ──→ image ──┘


    
We store the two parts separately:

    
image_url
meme_text


    
This connects to Manovich's database as a symbolic form: cultural material becomes a collection of elements that can be selected, organized, and recombined.

    
Because the images and texts remain separate, we can recombine them:


    
image 1 + text 3
image 3 + text 1
image 2 + text 2
