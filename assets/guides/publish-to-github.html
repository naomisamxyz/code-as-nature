Before you start

    
    
      
  • VS Code: installed, with your project open as a folder.
    • 
      
  • A free GitHub.com account: sign up at github.com if you don't have one yet.
    • 
      
  • A finished-enough project: any folder of files works. It doesn't need to be complete.
    • 
    

  


  

    
Open the Source Control panel

    
Click the branching icon in the left sidebar, or press Cmd/Ctrl + Shift + G.

    
This opens VS Code's controls for Git, which keeps a history of changes to your project. Opening the panel does not change the project.

  


  

    
Initialize the repository

    
If you see a button labeled Initialize Repository, click it.

    
Initializing tells Git to start tracking this folder. It creates a hidden .git folder where Git stores the project's history. Do this once per project.

  


  

    
Add a .gitignore

    
Create a new file at the top level of your project named exactly .gitignore, and put this line in it: .DS_Store

    

      
Not every file on your computer belongs in your project's history. macOS quietly drops an invisible housekeeping file called .DS_Store into folders you open in Finder. It's meaningless clutter, not part of your actual project.

      
A .gitignore lists files Git should not track. Those files stop appearing as changes and cannot be staged accidentally. This step is optional on operating systems that do not create .DS_Store.

    

  


  

    
Stage your changes

    
Hover over "Changes" and click + to stage everything at once, or stage individual files one at a time.

    
Staging selects which changes the next commit will save. It does not create the save point yet.

  


  

    
Commit

    
Type a message in the box at the top, then click ✓ Commit.

    

      
A commit is a snapshot of the staged changes in your project's history. The message briefly describes what changed.

      
For your very first commit, there's not much to describe yet. Something like "Initial commit" or "First version" is completely normal. Later on, describe what changed: "Fix header spacing," "Add contact page."

    

  


  

    
Publish

    
Click Publish Branch.

    

      
Everything so far has stayed on your own computer. GitHub doesn't know this project exists yet. Publishing does two things at once: it creates a new project on GitHub.com under your account, and it uploads your commit and its whole history there.

      
VS Code will open a browser tab to sign in, the first time only, then ask whether the project should be Public (anyone can view the files) or Private (just you, unless you invite others). If you plan to host this as a free website with GitHub Pages, it needs to be Public.

    

  


  

    
Every time after

    
Stage → write a commit message → click Sync Changes.

    
Each commit adds another snapshot to the history. Sync Changes sends new commits to the connected GitHub repository.
