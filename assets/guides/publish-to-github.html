Before you start

    
    
      
  • VS Code: installed, with your project open as a folder.
    • 
      
  • A free GitHub.com account: sign up at github.com if you don't have one yet.
    • 
      
  • A project folder with an index.html file
    • 
    

  


  

    
Open the Source Control panel

    
Click the branching icon in the left sidebar, or press Cmd/Ctrl + Shift + G.

    

      

        

          
Source Control panel:
opens VS Code's controls for Git, which keeps a history of changes to your project. Opening the panel does not change the project.

        

      

    

  


  

    
Initialize the repository

    
If you see a button labeled Initialize Repository, click it.

    

      

        

          
Initializing:
tells Git to start tracking this folder. It creates a hidden .git folder where Git stores the project's history. Do this once per project.

        

      

    

  


  

    
Add a .gitignore

    
Create a new file at the top level of your project named exactly .gitignore, and put this line in it: .DS_Store

    

      

        

          
.DS_Store:
an invisible housekeeping file macOS quietly drops into folders you open in Finder. Meaningless clutter, not part of your actual project.

          
.gitignore:
lists files Git should not track. Those files stop appearing as changes and cannot be staged accidentally. Optional on operating systems that do not create .DS_Store.

          
Windows:
doesn't create .DS_Store, but Windows Explorer sometimes drops its own clutter file, Thumbs.db. Add it as a second line in .gitignore if you see it show up.

        

      

    

  


  

    
Stage your changes

    
Hover over "Changes" and click + to stage everything at once, or stage individual files one at a time.

    

      

        

          
Staging:
selects which changes the next commit will save. It does not create the save point yet.

        

      

    

  


  

    
Commit

    
Type a message in the box at the top, then click ✓ Commit.

    

      

        

          
Commit:
a snapshot of the staged changes in your project's history. The message briefly describes what changed.

          
First commit message:
there's not much to describe yet - "Initial commit" or "First version" is completely normal. Later on, describe what changed: "Fix header spacing," "Add contact page."

        

      

    

  


  

    
Publish

    
Click Publish Branch.

    

      

        

          
Publishing:
creates a new project on GitHub.com under your account and uploads your commit and its whole history there. Until now, everything has stayed on your own computer.

          
Public vs. Private:
VS Code opens a browser tab to sign in, the first time only, then asks whether the project should be Public (anyone can view the files) or Private (just you, unless you invite others). GitHub Pages requires Public.

        

      

    

  


  

    
Every time after

    
Stage → write a commit message → click Sync Changes.

    

      

        

          
Sync Changes:
sends new commits to the connected GitHub repository. Each commit adds another snapshot to the history.

        

      

    

  


  

    
Make it a live website

    
GitHub can turn any public repository into a real website with its own URL, for free, using a feature called GitHub Pages. This part happens on github.com in a browser, and only needs doing once per project.
