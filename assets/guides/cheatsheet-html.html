Anatomy of an HTML tag

Before the full page example below, here's what one single tag is made of — every tag in HTML follows this same shape. The example below uses an anchor tag, the pair of <a> and </a>, which creates a link.

<a
  href="week1/index.html"
  class="week"
>
  Week 1
</a>
OPENING TAG

<a is the tag name — short for anchor, it's how you make a link. The tag name says what kind of element this is. Everything after it, up to the >, is an attribute: extra info about this specific element. href="week1/index.html" and class="week" are both attributes. The text in quotes is called a string — just a piece of text. You'll see that exact word again in CSS and JavaScript.

CONTENT

What actually shows on the page, sitting between the opening and closing tag. Here, that's the text “Week 1”.

CLOSING TAG

Marks where the element ends — same name as the opening tag, with a / in front. Not every tag has one, see below.

Tags that don't have a closing tag

Some tags never hold content, so there's nothing to put a closing tag around. These are called void elements. Attributes still go inside them exactly the same way — there's just no … in the middle and no </…> at the end.

<meta charset="UTF-8">
<img src="cat.jpg" alt="A sleeping cat">
<br>

The void elements you'll run into most: <meta>, <link>, <img>, <br>, <input> — remember, void just means no closing tag, so no content can sit "between" tags. Attributes still go inside the tag itself exactly as normal. Further down, every tag in the reference list shows which kind it is.

HTML Document Structure

Every HTML page starts from the same skeleton. The notes explain what each part actually does — and whether it's required or just good practice.

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta
    name="viewport"
    content="width=device-width, initial-scale=1.0"
  >
  <title>My Page</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>

  <header>
    <h1>Site Title</h1>
    <nav>
      <a href="#about">About</a>
      <a href="#work">Work</a>
    </nav>
  </header>

  <main>
    <p>Page content goes here.</p>
  </main>

  <footer>
    <p>&copy; 2026</p>
  </footer>

  <script src="script.js"></script>
</body>
</html>
HEAD · required

Required. Holds metadata — nothing inside is visible. <title> sets your browser-tab text, bookmark name, and the headline search engines show. <link rel="stylesheet" href="style.css"> is what connects this page to its CSS: rel says what kind of link it is, href says where to find the file.

BODY · required

Required in practice — everything visible lives inside <body>.

HEADER · optional

Optional — a <div> would work too. <header> tells screen readers and search engines this is the intro/nav area, which a generic <div> can't communicate.

MAIN · optional

Optional for rendering, but recommended — screen readers use <main> to jump straight to real content. A page should have at most one.

FOOTER · optional

Optional, same idea as <header> — purely semantic, for closing content like copyright or credits.

SCRIPT · optional

Optional — only needed if the page has JavaScript. Placed at the end of <body> on purpose: the page's HTML has already loaded by the time this runs, so the script can safely find and use elements above it.

Most relevant tags

Every tag below shows whether it needs a closing tag: written as <tag>…</tag> if it does, or with a void mark if it doesn't.

Structure

<div>…</div>
— generic container, no meaning of its own.
<span>…</span>
— generic inline container, for styling part of a line of text.
<header>…</header>
— top of the page; intro / branding area.
<nav>…</nav>
— a group of navigation links, your site's menu.
<main>…</main>
— the page's primary content, one per page.
<section>…</section>
— a thematic grouping of content, usually with its own heading.
<footer>…</footer>
— bottom of the page; closing info — credits, copyright, extra links.

Text

<h1>…</h1>
— heading. h1 through h6, in order of importance. One <h1> per page.
<p>…</p>
— a paragraph.
<a href>…</a>
— a link.
<strong>…</strong>
— marks text as important.
<em>…</em>
— marks text as emphasized.
<ul>…</ul>
— unordered list — items get bullet points, order doesn't matter.
<ol>…</ol>
— ordered list — items get numbers, order matters (like steps in a recipe).
<li>…</li>
— one item inside either kind of list.

Media

<img src="…" alt="…">
void — an image.
src="…" — where the file lives (more on file path vs. URL below).
alt="…" — the text description (more on alt text below).
<video controls>…</video>
— a video. controls is an attribute — add just that word inside the opening tag to show play/pause/volume controls.
<audio>…</audio>
— audio, same idea as video.
<iframe>…</iframe>
— embeds another page inline — more on this below.

Forms

<form>…</form>
— wraps a set of inputs meant to be submitted together.
<input type="…">
void — one field. The type attribute decides what it looks like and does:
type="text" — a normal text box.
type="checkbox" — a checkbox.
type="radio" — one choice among several.
type="email" / type="number" — a text box that expects that kind of value.
<button>…</button>
— a clickable button. Placed inside a <form>, it submits that form by default — that's the actual "submit" tag; add type="button" if you don't want that.
<label>…</label>
— a caption tied to a specific input.
<textarea>…</textarea>
— a multi-line text field. Use it instead of <input> whenever someone might type more than one line — a comment, a description — since a regular <input> only ever holds a single line.
<select>…</select>
— a dropdown menu.

Attributes worth knowing

These aren't tags on their own — they go inside an opening tag, the same spot as href or src. A few show up on almost anything.

class="…"
— a label you invent, used to style a group of elements the same way from CSS. Give several elements the same class, e.g. class="week", and one CSS rule styles all of them at once.
id="…"
— a label you invent for exactly one element on the whole page, no repeats. Used when you need to target that single element specifically, e.g. jumping to it with a link like #about.
alt="…"
— text description of an image, for screen readers and for when the image fails to load. Full explanation further down.
target="_blank"
— goes on a link (<a>). Makes it open in a new browser tab instead of replacing the page you're on.
data-*
— an attribute you make up yourself, starting with data-, e.g. data-week="3". The browser ignores it, but JavaScript can read it — a way to attach your own info to an element.

Embeds & previews

A few tags pull in images, media, or entire other pages. Walking through each one on its own.

1. Adding an image

<img src="cat.jpg" alt="A sleeping cat">

<img> is a void element (see above) — no closing tag, nothing goes between. src is an attribute pointing to the image file, the same way href points to a page in a link. It can be either kind of address: a plain file name or path like cat.jpg or images/cat.jpg when the image lives in your own project folder, or a full URL like https://example.com/cat.jpg when it's hosted somewhere else online. Use a file path for images you're supplying yourself; use a URL only when you actually mean to load someone else's hosted file.

2. Why alt text matters

alt is a second attribute on the same tag. It describes the image for screen readers, and it's what shows up as text if the image ever fails to load. For an image that's purely decorative — a background flourish with no real content — use alt="": empty, but still present. Leaving the attribute off entirely is different from leaving it empty, and only the empty version tells screen readers to skip it on purpose.

3. Keeping images from breaking your layout

That part is CSS's job, not HTML's — rules like max-width: 100% and aspect-ratio keep an image from overflowing or making the page jump while it loads. Covered properly in the CSS cheat sheet.

4. Linking to another page vs. embedding it live

There are two different ways to connect one page to another, and they do very different things.

<a href="diagram.html">Open the diagram</a>

A plain link. Clicking it navigates away — the browser leaves this page and loads diagram.html instead.

<iframe src="diagram.html" title="Diagram"></iframe>

An embed. This one does need a closing tag, even though nothing usually goes between it — it shows diagram.html live, inline, like a little window sitting inside the current page. The title attribute is required for accessibility: it's how a screen reader describes what's inside the window. In CSS, an iframe usually also gets border: 0 to remove the default border browsers put on it.

The course's main page (index.html) uses both, side by side: its syllabus section links out to the GitHub guide with a plain <a>, while its Computational Pipeline section embeds the diagram live with an <iframe>.

CSS inside HTML

CSS reaches a page in three ways — from most to least recommended. All three are HTML you write; only where the actual style rules live changes.

External file

<link rel="stylesheet" href="style.css">

Already covered above, in the HEAD note: one shared style.css file, linked from every page that needs it. Change the file once, every page updates — this is the one you'll use almost always.

Internal, written into the page

<style>
  body {
    background: black;
  }
</style>

<style>…</style> holds actual CSS rules — the same kind that would otherwise live in style.css — written directly into this one page instead. It goes in <head>, needs a closing tag, and only styles this page; nothing shared with any other.

Inline, on a single element

<p style="color: red;">Careful.</p>

A style attribute directly on one tag — no selector needed, since it can only ever apply to that single element. Fine for a quick test, but it doesn't scale: styling ten elements the same way means repeating the same style="…" ten times, instead of writing one CSS rule once. More on CSS itself in the CSS cheat sheet.

JS inside HTML

JavaScript reaches a page in a similar set of ways — a separate file, written into the page, or run straight from an attribute.

External file

<script src="script.js"></script>

Already covered above, in the SCRIPT note: one shared script file. Placed at the end of <body> so the page's HTML has already loaded by the time it runs.

Internal, written into the page

<script>
  console.log("hello");
</script>

<script>…</script> = JavaScript written directly into the page — the same idea as internal <style>, but for the kind of code that would otherwise live in a file like script.js. It runs automatically, the moment the browser reaches this point in the page — no click or other trigger needed.

Running JS straight from an attribute

A third way JavaScript shows up in HTML: directly inside an attribute like onclick, which runs a bit of JS whenever that element is clicked.

<button onclick="alert('Clicked ☺️!')">Click Me</button>

onclick is an attribute, same spot as href or src — except its value isn't a link or a description, it's an actual line of JavaScript. Unlike the <script> block above, which runs the moment the page loads, this code sits and waits — it only runs when the button is actually pressed, not before. Fine for a one-liner like this.

Once the logic is more than one line, onclick can just call a function defined elsewhere instead of holding all the code itself:

<button onclick="handleClick()">Click Me</button>

<script>
  function handleClick() {
    alert('Button clicked!');
  }
</script>

The button's onclick just names the function, handleClick(), and the actual logic lives in the <script> tag instead of being crammed into the attribute — the pattern you'll reach for once a click needs to do more than one thing. More on JavaScript itself in the JS cheat sheet, including why a separate file is usually cleaner than writing JS directly into the page or into an attribute.
