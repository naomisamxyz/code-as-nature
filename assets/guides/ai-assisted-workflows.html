AI-assisted workflows


    

      
Every tool shapes how you understand what you're working on, not just what you can build with it. Tools also come with politics: who owns them, whose labor and data built them, how much energy they use, what happens to what you put into them, and who benefits.

      
Learning to code has always been a bit of a treasure hunt. You search for solutions, read documentation, find code snippets someone shared online, take them apart, change them, and figure out how they work in your own project. Using AI isn't completely different from this. It can make that process much faster by helping you find solutions, debug problems, explain unfamiliar code, or work through an idea with you.

      
AI can help you write code, but you still need to understand enough to know what to ask for and how to ask for it, where the code goes, what it changes, and when something isn't working.

    

  


  

  

    
Chatbots


    

      

        

          
ChatGPT (OpenAI):
a good general-purpose starting point. Explains code, helps debug, revises writing, analyzes and generates images. Free tier available, with usage limits that change often. Check openai.com for the current ones.

          
Claude (Anthropic):
especially useful for reading code carefully, explaining what it thinks is wrong, and working through a problem in stages. Also strong for writing and revision. Free tier available, with usage limits that change often. Check claude.ai for the current ones.

          
Gemini (Google):
Google's general-purpose assistant. Its main advantage is its connection to Docs, Drive, and Search. Also useful for images and other media. Some features are free; Advanced is included with your CalArts Google account: sign in with @calarts.edu.

          
GitHub Copilot:
designed to work inside a code editor. Suggests the next line, answers questions about your code, can make changes across multiple files. Free plan has usage limits; verified students can get Copilot Student at no cost via GitHub's student program.

        

      

    

  


  

  

    
Coding agents

    
Work inside your terminal, editor, or project folder. Unlike a chatbot that only suggests code, an agent can inspect multiple files, edit them, run commands, and respond to the results. Useful for debugging and larger changes, but it also has more power to alter or delete things you didn't intend.


    

      

        
Agents

        

          
Gemini CLI (Google):
a free, open-source agent that runs in your terminal. Reads and edits files, runs shell commands, and can call out to other tools.

          
Codex (OpenAI):
OpenAI's coding agent, available in the terminal, IDE extensions, and the ChatGPT app. Can work locally or hand tasks off to a cloud sandbox.

          
Claude Code (Anthropic):
Anthropic's agent for the terminal and IDEs. Plans multi-step changes, edits across files, runs and tests its own work, and asks before doing anything destructive.

        

      

    


    
Try these after you are comfortable with files, the terminal, Git, and basic debugging.

    

      Warning
      
Coding agents can read, edit, and delete files directly. Avoid modes that allow changes without asking for permission, and only give access to folders you're comfortable modifying. Always commit your work with Git first so you can undo unwanted changes.

    

  


  

  

    
Clear instructions

    
Before giving AI a task, tell it how you want it to work with you. This helps prevent it from acting like an overambitious intern and changing, adding, or "improving" things you never asked for.


    
    
      
  • 
        
    Intention + boundaries
    
        
    Explain what you're trying to do, what the scope is, and how you want to approach it. Tell it to always ask for permission before making any changes.
    
        
    "I'm building a simple Unity interaction where clicking an object changes its material. I want to build this one step at a time using basic C# that I can understand. Start by helping me detect when the object is clicked. Don't write the material-changing part yet. Always ask for my permission before making any changes. Only do what I ask you to, keep your answers short and precise."
    
      
    • 
      
  • 
        
    Give it your input
    
        
    Give it the relevant code, files, errors, or context. Let it understand what already exists before changing anything.
    
        
    "Here is my current script. Read it and explain how it works. Don't change or rewrite anything yet."
    
      
    • 
      
  • 
        
    Give exact instructions + approach
    
        
    Tell it precisely what you want changed and how you want it to approach the code. If you're learning or practicing something specific, tell it which concepts, methods, or structures to use.
    
        
    "Change the script so clicking the object switches between two materials. Use a bool to keep track of which material is currently active and an if / else statement to decide which material to apply when the object is clicked. Store both materials as public variables so I can assign them in the Unity Inspector. Keep the code simple and don't introduce additional systems or concepts."
    
      
    • 
      
  • 
        
    Repeat back
    
        
    Before it starts, make sure it understood your instructions.
    
        
    "Before you do anything, repeat back what you understood and how you're going to approach it."
    
      
    • 
      
  • 
        
    Execute
    
        
    After any necessary revisions of step 4, tell it to go ahead without expanding the scope.
    
        
    "Only make the changes we agreed on. Don't change anything else."
    
      
    • 
      
  • 
        
    Test + debug
    
        
    Test the change before moving on. If something doesn't work, give AI the exact error message and describe what happened. Ask it to identify the problem before changing more code.
    
        
    "The material isn't changing when I click. There are no errors in the Console. Help me figure out where the problem is. Let's test one thing at a time, and don't change the code until we know what is causing it."
