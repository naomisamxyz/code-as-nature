AI-assisted workflows


  

    
Every tool shapes how you understand what you're working on, not just what you can build with it. Each comes with politics: who owns it, whose labor and data built it, how much energy it uses, what happens to what you type, and who benefits. Understand these tradeoffs before choosing a tool.

    
AI can speed up your process and be a useful creative tool. The goal is understanding the relationship between your decisions and what the work does. Use it as a debugger, critic, explainer, or pair programmer.

  


  

  

    
Chatbots


    

      

        

          
ChatGPT (OpenAI):
a good general-purpose starting point. Explains code, helps debug, revises writing, analyzes and generates images. Free tier available, with usage limits that change often. Check openai.com for the current ones.

          
Claude (Anthropic):
especially useful for reading code carefully, explaining what it thinks is wrong, and working through a problem in stages. Also strong for writing and revision. Free tier available, with usage limits that change often. Check claude.ai for the current ones.

          
Gemini (Google):
Google's general-purpose assistant. Its main advantage is its connection to Docs, Drive, and Search. Also useful for images and other media. Some features are free; Advanced is included with your CalArts Google account: sign in with @calarts.edu.

          
GitHub Copilot:
designed to work inside a code editor. Suggests the next line, answers questions about your code, can make changes across multiple files. Free plan has usage limits; verified students can get Copilot Student at no cost via GitHub's student program.

        

      

    

  


  

  

    
Coding agents

    
Work inside your terminal, editor, or project folder. Unlike a chatbot that only suggests code, an agent can inspect multiple files, edit them, run commands, and respond to the results. Useful for debugging and larger changes, but it also has more power to alter or delete things you didn't intend.

Prompt writing

    
Understanding code helps you know what to ask and how to ask for it.

    
    
      
  1. Name the problem yourself first.
    2. 
      
  2. Give it the smallest useful bit of code, the exact error, and what you expected vs. what happened.
    3. 
      
  3. Ask for a diagnosis before a rewrite. Don't add a line you can't explain yourself.
    4. 
      
  4. Change one thing at a time, and run it after each change.
    5. 
      
  5. Check the result yourself: open the page, resize it, click everything, check the console. If a tool edited files directly, check exactly what changed before trusting it.
    6. 
      
  6. Keep private material (passwords, API keys, other people's unpublished work) out of the prompt, and keep a working version before you start.
